# Spec 0009：v0.4.1 资产类别与研究场景收敛

## 状态

**Proposed；仅整理文档、产品边界和验收义务，未授权代码、测试实现、GitHub Issue 或发布状态变更。**

基线为当前 `main` / `v0.4.0`。本文不改写 Spec 0008 及 Amendment C/D/E/F 的历史语境，也不把历史 screening 设计或静态资格证据表述为当前已交付能力。本文用于定义 v0.4.1 的后续实施范围、二维能力矩阵和验收顺序。

## 决策摘要

v0.4.1 采用“资产类别 × 研究场景”的二维产品模型。所有已有产品意图保留，但不再把股票、ETF、期权、指数和市场聚合混在一个能力清单中，也不再把市场观察与市场筛选当作同一个 workflow。

本版本的产品域分为：

1. A 股普通股票：项目的 P0 核心能力；
2. 指数与市场聚合：`market_overview_research@2.0` 的 P0 市场能力；
3. ETF：独立于股票分母的 P0/P1 扩展；
4. ETF 期权：隔离的 P2 实验扩展；
5. 市场筛选：保留产品意图并重构为独立 P1 产品链，公开启用前必须完成独立验收；
6. 债券、一般基金及其他衍生品：P3 延期，另立资产类别规格；
7. 共享研究底座：身份、时点、来源、证据、coverage、结果信封和安装分发，作为所有产品域的共同 Interface。

## 问题与目标

v0.4.0 已交付唯一公共 `run --request` 入口、窄 ResearchTask、固定 workflow、统一结果信封和市场总览能力，但当前代码与文档仍混合了不同资产类别、不同研究目的和不同验收层级。特别是：

- `market_overview_research@2.0` 描述市场状态，不生成候选证券；
- `market_screen_research@1.0` 设计上生成 A 股候选证券，但当前运行时在来源或 artifact I/O 前拒绝；
- ETF、ETF 期权、盘中和分时复盘有独立的来源、单位和时间契约；
- 债券、一般基金和其他衍生品没有当前可接受的公共契约；
- 共享结果、证据和发布工具被各领域实现与维护工具交叉引用。

v0.4.1 的目标是：

1. 用二维分类给每项能力唯一归属；
2. 保留仍有产品价值的能力和实验能力，不因瘦身误删产品意图；
3. 将市场观察、市场筛选和单标的研究拆成独立产品链；
4. 为每条产品链定义独立的输入、输出、失败和证据验收；
5. 把延期资产类别显式标为未来范围，不使用股票、ETF 或指数数据代理；
6. 在不改变公共 JSON 和调用入口的前提下，为后续代码重构建立可审查边界。

## 二维分类模型

### 资产类别维度

| asset_class | 定义 | v0.4.1 状态 |
|---|---|---|
| `a_share_equity` | SSE、SZSE、BSE 的人民币普通股票 | `retain`, P0 |
| `etf` | 当前支持范围内的 SSE ETF | `retain`, P0/P1 |
| `etf_option` | 指定 ETF 标的的认购/认沽期权合约 | `retain`, P2 |
| `index` | 固定宽基指数及其市场观察引用 | `retain`, P0 |
| `market_aggregate` | 行业、涨跌停、交易会话和市场信号聚合 | `retain`, P0 |
| `bond` | 债券及债券发行主体 | `defer`, P3 |
| `fund` | ETF 之外的一般基金 | `defer`, P3 |
| `other_derivative` | 股票期权、期货、权证等其他衍生品 | `defer`, P3 |

`etf` 虽属于基金的金融分类，在本项目中仍作为独立 `asset_class`，因为其身份、单位、行情来源和交叉核验契约不同。`index` 和 `market_aggregate` 是市场观察对象，不进入 A 股普通股票筛选分母。

### 研究场景维度

| research_scene | 目的 |
|---|---|
| `identity_scope` | 解析规范身份、证券类别、交易所、上市状态和适用时点 |
| `market_observation` | 获取价格、走势、成交、会话或已完成交易日序列 |
| `valuation_fundamentals` | 形成估值、财务输入和同口径比较 |
| `materials_events` | 获取研报、公告、F10、新闻、资金和公司事件 |
| `market_signals` | 形成板块、题材、涨跌停、热度、监控和异常信号 |
| `screening_ranking` | 从完整股票分母形成可重复的候选集合和排序 |
| `workflow_orchestration` | 编排已版本化的窄 ResearchTask |
| `evidence_result` | 保存证据、结果、coverage、失败、冲突和可恢复 artifact |

每项能力在矩阵中必须同时声明 `asset_class`、`research_scene`、`status`、`priority` 和验收证据。未声明的资产类别不得由调用者或 Agent 推断支持。

## 产品范围与能力契约

### A 股普通股票：P0 核心

保留 `security_identity`、`market_trend`、`security_valuation`、`valuation_compare`、`research_content`、`capital_events`、`market_signals` 及 `single_security_research@1.0`。`single_security_valuation`、`valuation_comparison`、`theme_report_research` 和 `new_security_research` 作为已有固定 workflow 保持兼容，但共享同一窄任务契约。

核心验收必须证明：

- 规范身份、交易所、证券类别和研究日期均可追溯；
- 估值必须先证明发行主体证券类别范围；
- 行情、材料和事件保留来源、时点、单位、冲突和局部失败；
- 结果状态、coverage 和限制字段不因重构改变；
- 复制安装后的公共入口仍只输出一个版本化 JSON。

### 指数与市场聚合：P0 核心

保留 `market_overview_research@2.0`、`market_trading_session`、`major_broad_indices` 和现有市场信号增强。市场总览固定 15 项 inventory，其中 12 项按 tier 和适用性执行，`whole_market_turnover`、`whole_market_margin` 和 `market_wide_intraday` 保留稳定 `unsupported`。

市场总览不得：

- 生成证券候选排名；
- 以单只股票、ETF、单一指数或板块代理全市场结论；
- 将 unsupported、未请求或来源失败折叠为空集；
- 把固定指数观察解释为全部证券行情。

### 市场筛选：P1 延期为不支持

保留 `market_screen_research@1.0` 的未来产品意图，但 v0.4.1 不提供公共 screening。当前 `public_state` 为 `deferred`，对用户表现为不支持；运行时继续在 source 或 artifact I/O 前稳定拒绝。

三所时点 Universe、批量因子、确定性排名、候选深研和 screening Result Artifact 的实现与 release gate 从 v0.4.1 的有效交付范围中移出，已有内部模块、测试和历史证据只作为延期 provenance 保留。重新启用 screening 需要另一个版本的 source qualification、owner contract、PIT ledger、安装 E2E 和同候选发布验收。

### ETF：P0/P1 独立扩展

保留 `etf_market`，ETF 不进入 A 股普通股票筛选分母。ETF 身份、价格、涨跌、成交量、成交额、单位转换和交叉核验必须有独立契约。

### ETF 期权：P2 实验扩展

保留 `etf_options` 的指定标的范围，但独立维护合约月份、到期日、认购/认沽、行权价、标准/调整类型、报价时点、空集和限制语义。供应商 Greeks / IV 不自动变成本地计算值。

### 盘中与分时复盘：P2 实验扩展

保留 `intraday_market_signal` 和 `intraday_replay`。当前盘中快照、已完成交易日分时序列、交易阶段和覆盖状态必须分开；未实时验证继续如实记录，不影响核心股票和市场总览的静态验收。

### 债券、一般基金和其他衍生品：P3 延期

0.4.1 不新增债券、一般基金、股票期权、期货或权证的公共 task。它们需要独立的身份、行情、估值、权限、来源和验收规格，不能复用股票或 ETF 的字段推断支持。

## 状态与兼容边界

矩阵只使用三种状态：

- `retain`：保持现有契约，仅允许文档、测试和内部实现整理；
- `refactor`：保留产品意图和兼容入口，允许重构实现，必须先完成独立验收；
- `defer`：保留需求记录和边界说明，但不在当前版本声明公共支持。

0.4.1 不改变 `schema_version: "1.0"`、`run --request`、`--output`、统一结果信封、已有有效 task ID 或历史发布证据。`market_screen_research` 保持稳定拒绝并记录延期/不支持状态；`market_overview_research@1.0` 的拒绝行为也保持稳定。

## 优先级与发布门禁

### P0：0.4.1 核心发布门禁

- 资产类别与研究场景契约；
- 共享结果、evidence 和错误折叠；
- A 股核心窄任务及单标的研究；
- 市场总览 `@2.0` 的 15 项 inventory、12 项可执行能力和 3 项 unsupported；
- ETF 基础行情；
- 当前文档、模板和安装分发边界；
- `core`、`installed` 和文档/分发检查。

### P1：0.4.1 延期范围

时点化 A 股 Universe、因子资格、确定性排名、候选深研、screening Result Artifact 和公共 screening 路由均延期。发布记录必须写明 `market_screen_research` 为 deferred/unsupported，并保留稳定拒绝；不得把内部模块或离线夹具写成公开支持。P1 不再阻塞 P0 发布。

### P2：扩展能力门禁

- ETF 期权契约和实验来源；
- 盘中快照和分时复盘；
- 可选 live probe、安装加载和失败边界。

P2 不得阻塞 P0，但必须保持真实状态和明确的实验边界。

### P3：未来规格

债券、一般基金、其他期权/期货、开放式选股、自动交易和投资动作建议另立规格。

## 最终发布门禁

发布前必须对一个冻结 clean candidate 完成：

1. P0 任务与公共 JSON 契约验证；
2. P1 状态 readback，确认 screening 未被误标为已支持；
3. P2 实验能力的安装、离线和失败边界记录；
4. `uv` 管理的 Python 3.14 开发环境下的 core / installed / release profile；
5. 公共运行时仍满足 Python 3.12+ 的安装契约；
6. 当前文档链接、双语说明、模板、敏感路径和分发树检查；
7. 历史 Spec、ADR、v0.3.0 / v0.4.0 evidence 和 release 记录未被改写。

本 Spec 完成只表示范围和验收边界已定义，不表示任何实现、Ticket、来源、release evidence、tag 或 GitHub Release 已完成。
