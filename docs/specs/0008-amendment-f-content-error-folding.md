# Spec 0008 Amendment F：补齐保留内容路径的错误折叠修复责任

## 授权与产品边界

本修订依据维护者已给出的自主推进至 0.4.0 完成、普通缺陷继续修复及 Tracker／指定集成分支同步授权，补齐最终验收发现的一项历史生产责任。不增加产品功能，不改变免费匿名边界，也不恢复已退出功能。

Amendment C/D 的功能处置，以及 Amendment E 的两项盘中实时验证豁免继续有效：十五个清单槽位、十二项可执行能力、三项 unsupported、四项 core／八项 standard 保持不变；正式来源／应用清单仍由当前公开计划导出，不因本修复缩小。无需等待盘中交易窗口。

## 修复义务

保留的研究材料路径在同一 operation 返回多条等价公共错误时，会生成重复 canonical 错误 ID 和引用，随后被严格 ownership 校验拒绝。生产 F10 多 category 的离线公共命令对照证明了该缺陷；生产 QA 的同类错误也可到达既有单证券研究的 materials leaf。真实失败的具体 Adapter 尚不能唯一归因，市场总览的 market-flash 路线也未被证明自然触发该缺陷。

新增窄范围 Ticket #124 负责统一结果中等价内容错误与引用的规范化。公共 SourceError payload、稳定 ID 规则、details schema、真实 source-result 状态和 attempted 事实保持不变；不同错误及不同所有者的区别保留。外部重复 ID、错属、孤立引用和 payload 漂移继续失败关闭，不通过扩大私有字段或放宽 validator 获得表面成功。

该任务的完整 Objective、Scope、Acceptance Criteria 和 Verification 由 Tracker 回读定义快照绑定；修复及复制安装的直接／单证券消费者回归必须先完成。不会把未覆盖的历史生产修改塞入 #105 的受限 sanitizer 范围或 #98 的冻结证明职责。

## DAG 责任与依赖

新增 #124，Hard predecessor 为 #97；将 #98 的直接 Hard predecessor 从 #97 改为 #124，形成 `#97 → #124 → #98`。其余节点、原生依赖和退出处置不变。有效图由十六张 Ticket／二十七条 hard edges 变为十七张 Ticket／二十八条 hard edges；所有有效节点仍到达 #98。

#97 提供已交付的安装／分发及公共命令 seam。新修复任务提供符合既有公共错误契约的生产结果和相关回归，#98 消费修复后的最终安装包，完成适用的真实来源证明与发布证据。

此处仅改变遗漏修复义务的显式归属和完成顺序，不自动接受新任务、不重新接受历史源码、不更改任何既有产品验收语义。既有任务的证据保留原身份，受影响的消费者须有明确适用性证明；实际新增失败按原有重开规则处理。

## 最终验收

#124 在固定基线上完成最小修复、公共接口 causal RED／GREEN、必要完整检查及独立 Standards／Spec 审查后，方可交付 #98。

#98 的同候选、新鲜度、脱敏、计划导出的完整分母和精确应用覆盖要求不变。修复前的成功与失败均保留原始候选身份，不能重标为修复后候选的最终来源证明。真实三所会话与固定四指数的已完成交易日市场总览 E2E 继续必需；盘中实时验证继续按 E 豁免。

本修订不扩大 main、tag、GitHub Release、远端 CI 或 Spec parent 关闭权限。
