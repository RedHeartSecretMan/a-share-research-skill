# Spec 0005：研究级盘中行情快照

## 状态

已实现；v0.2.0 交付通过 `intraday_market_signal` 提供。两个来源 operation 仍是实验来源，单次成功不构成生产准入。

## 背景

当前 Skill 可以取得最近完成交易日行情、历史走势和 ETF/ETF 期权快照，并已通过 `intraday_market_signal` 在稳定 ResearchTask Interface 上提供单只 A 股的当日盘中状态。该能力仍使用实验来源，Agent 必须保留其受限或阻断状态，不能把一次观测升级为生产来源资格。

本规格增加研究级近实时快照，而不是交易级行情服务。它只负责取得、标准化、交叉核验和裁决证据；市场含义、风险与结论继续由 Agent 按分析边界形成。

## 目标

- 对当前北京时间交易日的一只规范 SSE 或 SZSE A 股形成单次盘中行情快照；
- 明确证券身份、交易日、盘中交易会话状态、盘中价格类型、来源观测时间和获取时间；
- 提供最新价格、开高低、盘中昨收基准、盘中累计成交量和成交额；
- 使用通达信同一观测作为适用快照字段基准，使用腾讯作为必须成功的独立核心价格交叉观测；
- 在来源缺失、陈旧、错证券、时点不兼容、会话不明或核心价格冲突时失败关闭；
- 保留所有来源证据、冲突、不可用字段、限制和计算谱系，使 Agent 能在结果未阻断时继续研究。

## 非目标

- 分钟 K 线、逐笔、盘口队列、持续轮询、订阅、流式推送或批量证券快照；
- 交易级时延、可用性或 SLA，以及自动交易、下单或高频用途；
- 百度或其他尚未注册来源、来源自动接管、单源实验报价或多源任选；
- 把本能力的实验 operation 描述为已完成生产准入；
- 趋势、强弱、异动原因、买卖方向或其他市场分析结论；
- 历史盘中重建、盘后回放或以最近收盘冒充当前盘中状态。

## Public ResearchTask Interface

本能力只通过现有公共入口执行：

```text
<python> <skill-root>/scripts/entrypoint.py run --request <research-task.json> [--output <file>]
```

请求继续使用当前 ResearchTask schema，并满足以下约束：

- `task_type` 必须为 `intraday_market_signal`；
- `subjects` 恰好包含一个能够解析为规范 SSE 或 SZSE A 股的标的；
- `as_of` 必须是实际获取时的北京时间日期；历史日期和未来日期均返回结构化 `blocked`；
- `window` 为 `null`，因为本任务不是期间或序列查询；
- `source_policy.allow_experimental` 必须为 `true`；
- 不增加顶层 `intraday` 命令，也不保留其他兼容入口。

`mootdx==0.11.7` 是本能力锁定的按需可选依赖。缺少依赖只使本任务以 `missing_optional_dependency` 阻断，不影响核心 CLI 或其他 ResearchTask，也不得静默换源。

## 来源 operation 与角色

### 通达信快照基准

新的 `mootdx` 盘中 operation 从同一次采集取得价格、开高低、昨收、成交量和成交额。其 quote 只有服务器时分秒时，必须由该 operation 同次取得的最新日线补足交易日期，并同时满足：

- quote 与日线属于同一规范证券；
- 日线日期等于请求 `as_of`；
- quote 的服务器时间、日线日期和实际获取时间能形成适用会话；
- 日线缺失、日期不一致或拼接关系不可证明时失败关闭。

通达信 `vol` 只有在 operation 已验证其单位为手时才能乘以 100 规范为股；`amount` 只有在已验证为人民币元时才能输出。不得用猜测单位形成数值。

### 腾讯强制交叉观测

腾讯盘中 operation 可以复用 `tencent_daily_line@1` 已验证的网络、身份和 schema 边界，但必须建立独立的盘中结果契约。它核验规范证券、交易日、盘中交易会话状态、盘中价格类型、最新价、开高低和可比较的盘中昨收基准。

腾讯不是可接管通达信的 fallback。任一 operation 失败、返回错证券或不能形成兼容观测时，任务整体 `blocked`，同时保留已取得的另一侧诊断。

## 单一快照与交叉规则

通达信同一观测提供适用快照字段，腾讯只提供强制独立交叉证据。不得把腾讯较晚时点的成交量与通达信较早时点的成交额拼接，也不得按字段挑选对结果更有利的来源。

两路观测必须满足：

- 规范证券身份和交易日相同；
- 盘中交易会话状态和盘中价格类型兼容；
- 活跃交易阶段的来源观测间隔不超过 60 秒；
- 最新价和 OHLC 在 A 股 0.01 元最小变动单位规范化后完全一致；
- 盘中昨收基准只有在语义和值均可比较时才采用；
- 成交量和成交额只有在单位、累计范围和来源时点可比时才比较。

任何 JSON 边界价格都使用十进制定点字符串。不得把 pandas 或 Python 二进制浮点的表示噪声当作价格冲突，也不得用容差掩盖真实的最小变动单位差异。

## 会话与新鲜度

盘中交易会话状态包括：

- `opening_auction`：开盘集合竞价；
- `continuous`：上午或下午连续竞价；
- `midday_break`：午间休市；
- `closing_auction`：收盘集合竞价。

盘前、盘后、非交易日或会话无法确认时，本任务 `blocked`。不得只依据本机时钟判断会话；当前北京时间、两路来源交易日和来源观测时间必须共同成立。

活跃竞价阶段要求每个来源观测在获取时的年龄不超过 60 秒，两路观测也必须处于兼容的 60 秒窗口。60 秒是首版研究目标，不是 SLA。来源时间缺失、缓存状态未知或超过阈值时失败关闭。

午间休市可以保留上午最后观测，不因休市期间自然增长的年龄自动阻断，但必须同时满足：

- 两路来源都定位到当前交易日的上午最后兼容观测；
- 当前会话能够确认为 `midday_break`；
- 结果明确说明价格和累计成交停留在上午最后观测时点。

公共 CLI 每次调用都重新采集两路来源。除调用者显式使用现有 `--output` 保存最终结果外，本能力不创建磁盘缓存、数据库或全局配置。

## 价格与成交语义

连续竞价中的 `latest_traded` 表示来源报告的最近实际成交价。集合竞价中尚未形成实际成交的价格只能标记为 `indicative_auction`；如果两路来源不能明确并兼容地表达指示性竞价价格，则该阶段 `blocked`，不得沿用上一笔成交冒充当前竞价价格。

盘中累计成交量和成交额表示从当前交易日开始至通达信基准观测时点的累计值，规范单位分别为股和人民币元。午间休市保留上午最后累计值。零值只有在来源明确确认尚未成交或停牌时才有效；缺失、负值、单位不明或累计范围不明均不可采用。

盘中昨收基准可能是实际前收盘价或除权参考价。只有两路来源语义和值均兼容时才输出并允许计算涨跌；公司行动导致语义不明时，保留当前价和 OHLC 快照，将昨收标为不可用，并禁止生成涨跌额或涨跌幅。这一非核心缺口不单独使结果 `blocked`。

## 停牌

停牌不是来源失败。只有两路独立来源共同确认证券在当前适用会话停牌时，才形成 `limited` 的停牌状态快照：

- `trading_status` 明确为 `suspended`；
- 最新价和 OHLC 标为不适用，而不是填零或复制昨收；
- 成交量和成交额只有在两路明确确认无成交时才为零；
- 保留昨收或参考价时仍须满足其语义边界。

单纯的空响应、零成交量、价格等于昨收或来源超时都不能独立证明停牌；无法区分停牌与来源失败时任务 `blocked`。

## 结果契约

结果继续遵守公共 ResearchResult 的进程和 JSON 语义：有效的 `limited` / `blocked` 领域结果退出码为 0，调用、I/O 或内部协议失败使用非零退出码和脱敏 stderr。

结果至少保留：

- 规范 `subject`、请求 `as_of` 和实际交易日；
- `session_state`、`trading_status` 和 `price_type`；
- 最新价、开高低、盘中昨收基准及其可用状态；
- 盘中累计成交量、成交额及规范单位；
- 通达信基准观测时间、腾讯交叉观测时间、获取时间和观测间隔；
- 两个版本化 `source_operation`、证据定位和字段血缘；
- `brief`、`evidence`、`conflicts`、`source_errors`、`limitations` 与不可用字段原因。

当前两个 operation 都是实验来源，因此正常成交快照和已确认停牌快照最高为 `limited`，不能达到 `supported`。以下任一情况使任务整体 `blocked`：

- 身份、交易日、会话或盘中价格类型不兼容；
- 活跃阶段任一观测陈旧、缺少来源时间或两路间隔超过 60 秒；
- 最新价或 OHLC 在规范精度下冲突；
- 任一必需 operation 失败或来源策略不允许实验来源；
- 非停牌状态下最新价、OHLC、累计成交量或累计成交额不可采用；
- 盘前、盘后、非交易日、历史请求或未来请求。

## Agent 边界

CLI 不输出趋势、强弱、催化剂、异常原因、买卖方向或投资行动建议。Agent 可以在 `limited` 结果上基于明确字段、时点和限制形成标注为推断的研究判断；`blocked` 时只能说明缺口与后续所需证据。

## 验收门槛

实现必须在公共 `entrypoint.py run --request` seam 采用测试驱动开发，并至少覆盖：

1. 当前 SSE 与 SZSE 正常连续竞价快照均形成 `limited`；
2. 价格按 0.01 元规范化，二进制浮点噪声不形成假冲突，真实一跳差异形成冲突；
3. 通达信 quote 与同次最新日线补足日期，错证券、旧日期、未来日期和缺日线失败关闭；
4. 来源年龄、两路 60 秒窗口、午间休市例外和未知缓存状态；
5. 开盘/收盘集合竞价的指示性价格、连续竞价成交价及语义不兼容；
6. 盘前、盘后、非交易日和未知会话；
7. 通达信手转股、成交额人民币元、零值、负值、缺失单位和跨时点禁止拼接；
8. 双源停牌确认、单源零值、空响应和无法判定停牌；
9. 除权日昨收可比、昨收语义不明以及禁算涨跌；
10. 任一来源失败、错证券、schema 漂移、核心价格冲突和来源策略拒绝；
11. `mootdx` 缺失只阻断本能力，其他任务不受影响；
12. 输出完整保留证据、来源时间、获取时间、字段血缘、冲突、错误和限制。

默认测试必须完全离线，只使用合成响应，不提交真实来源数据、缓存或用户配置。单独提供显式 live probe，至少覆盖一只 SSE 和一只 SZSE A 股；它不进入普通 CI，不更新夹具，也不能把单次成功升级为生产准入。

实现完成前还必须通过 Python 3.12 全量 unittest、Ruff、strict mypy、Skill validator、`git diff --check`，并分别完成 Standards 与 Spec 审查。

## 既有决定

本规格遵循而不取代以下决定：

- ADR-0002：事实、推断和来源角色分离；
- ADR-0003：研究时点、证据时点和获取时间分离；
- ADR-0009：按 Adapter operation 而不是供应商品牌完成准入；
- ADR-0015：实验免费来源可以交叉核验，但不能独立形成 `supported`；
- ADR-0016：研究能力可以声明版本锁定的可选依赖，缺失时明确失败关闭。

候选来源组合和快照基准角色属于本能力的可替换实现规格，不新建 ADR；未来 operation 完成生产准入时，可以在不改变公共任务意图的前提下另行修订来源策略和结果上限。
