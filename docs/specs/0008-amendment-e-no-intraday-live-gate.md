# Spec 0008 Amendment E：本次交付不要求盘中实时验证

> 后续内容错误修复的责任与执行顺序见 [Amendment F](0008-amendment-f-content-error-folding.md)；本修订的盘中实时验证豁免继续有效。

## 授权与适用边界

维护者于 2026-10-16 明确要求“没必要盘中验证”。本修订取消 0.4.0 交付对既有单证券盘中功能的强制实时交易窗口验证，优先于此前与此冲突的全量 fresh live attempt 或盘中等待要求；其余未冲突的功能、来源真实性和质量要求继续有效。

本修订调整验证责任，不删除单证券盘中功能、不重新引入已退出功能，也不将未实时验证解释为功能不支持。Amendment D 的十五个清单槽位、十二项可执行能力、三项 unsupported、四项 core／八项 standard 及十六张 Ticket／二十七条 hard edges 保持不变。

## 明确的实时验证豁免

本次交付仅对下列既有应用免除 fresh 真实盘中来源调用义务：

| capability | producer operation | 本次所需证明 |
| --- | --- | --- |
| `intraday_market_snapshot` | `tencent_intraday_snapshot@1` | 同候选安装与加载事实、相关离线行为及失败边界回归；明确记录本次未进行盘中实时验证。 |
| `intraday_market_snapshot` | `tongdaxin_intraday_snapshot@1` | 同候选安装与加载事实、相关离线行为及失败边界回归；明确记录本次未进行盘中实时验证。 |

单证券盘中功能、原接口、来源与时点校验及离线回归继续保留。本次不需要等待下一交易时段，也不需要为满足发布门禁而执行其盘中公共画像。已有历史来源证据可以作为原身份的补充材料，不得重标为当前候选的实时证明。

## 最终证据与验收

#98 仍须从实际公开计划和资格定义确定完整 producer／application 清单，不得为了通过门禁删去上述两项、缩小公开分母或伪造计划。本次 live 验证的适用集合只排除表内两项，必须显式记录排除项、授权理由、离线及安装证据和“本次未实时验证”的结论。

原始 attempt、`attempted`、source result、安装加载和整体来源覆盖事实必须保持真实：未调用不能写成已尝试，未实时验证不能写成来源成功，也不能把完整公开集合误报为全部 fresh live 验证完成。最终 evidence／matrix 可以区分完整公开清单与本次必须实时验证的适用集合；门禁只要求后者闭合，并要求表内两项的安装及离线证明齐备。若现有工具仅支持全量实时闭合，由 #98 作最小明确调整，保留历史 v0.3.0 语义和严格校验，拒绝任意未知豁免项，不引入按候选 SHA 放行的特例。

仍发布的 `market_trading_session` 与 `major_broad_indices` 必须保留合格真实来源及三所会话／固定四指数市场总览 E2E。总览可按实际已完成交易日验证，不要求实时盘中采样；其他仍适用的来源证明、同候选身份、新鲜度和失败事实要求不变。已退出的全市场成交额、全市场两融及全市场盘中仍按 D 明确 unsupported。

Python 3.12 完整测试、静态检查、Skill、安装／分发、文档和独立 Standards／Spec 审查继续执行。范围之外的普通代码缺陷继续修复。本修订不豁免测试失败、缺少安装依赖或其他保留能力的验收责任。

## 责任与验收影响

#96 的当前实现及普通失败处理修复义务不变；#97 保留真实安装、离线回归和准确文档责任；#98 负责本修订的验证适用性、最终证据和 matrix。无需因本修订重开已验收的产品 Ticket；未验收的下游工作须消费更新后的定义。

本修订不自动接受任何 Ticket。最终完成仍须满足当前定义下的全部有效义务、必要检查及独立审查，并回读确认已验收集成点与授权远端分支一致。现有 main、标签及 Release 发布权限不因本修订扩大。
