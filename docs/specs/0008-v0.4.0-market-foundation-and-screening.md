## 决策摘要

v0.4.0 合并原先分散讨论的“综合市场基础”和“全 A 股筛选”两条产品链，一次交付：

1. 补齐 `market_overview_research` 的五项正式市场能力；
2. 建立 SSE、SZSE、BSE 三交易所的时点化 A 股证券池；
3. 以能力需求驱动来源候选资格，不恢复固定 47 端点计划；
4. 对全 A 股执行有界批量采集和确定性研究优先级排名；
5. 将大型结果保存为调用者显式指定、可恢复、写一次且可验篡改的分区 JSONL 结果包；
6. 对有界数量的候选复用综合单标的研究，保留局部失败和完整谱系；
7. 通过 installed-copy 公共入口、中文案例、分发检查和冻结候选发布证明闭合 v0.4.0。

本版本不生成买入、卖出、持有、目标价、仓位、杠杆、止损或自动交易指令。筛选分数表示“后续研究优先级”，不表示投资评级、预期收益或适合某个投资者。

## 修订关系与版本边界

- Spec 0007 Amendment A 仍是 v0.3.0 的已交付权威；本文不改写其历史完成证据。
- 本文接收 Spec 0007 明确延期的市场基础、全 A 股批量扫描、确定性排名、未排名候选、候选深研和大型结果包。
- `schema_version: "1.0"` 继续表示 ResearchTask 和统一研究结果信封，不因新增 workflow 而变化。
- workflow 改为按 ID 独立版本化，不再用一个全局常量约束全部 workflow：
  - `market_overview_research@2.0` 取代当前实现中的 `@1.0`；
  - 新增 `market_screen_research@1.0`；
  - 其他已发布 workflow 继续使用各自的 `@1.0`。
- 最终 v0.4.0 运行树不保留 `market_overview_research@1.0` 兼容层，也不静默转换旧请求。需要旧行为的调用者应固定使用 v0.3.0 发布物。

## 用户目标

1. 作为 A 股研究用户，我希望在任意时间运行完成交易日筛选，而不是等待盘中窗口。
2. 作为市场研究用户，我希望综合市场结果明确包含交易会话、主要宽基指数、全市场成交额、全市场两融和可选盘中全市场快照，而不是以单只证券、ETF、单一指数或板块代理整体市场。
3. 作为全市场研究用户，我希望证券池同时覆盖 SSE、SZSE 和 BSE，并能证明每条证券在研究时点的身份与上市状态。
4. 作为研究用户，我希望排名由固定版本的因子、权重、缺失规则和排序规则产生，Agent 不能临时改权重或补值。
5. 作为研究用户，我希望缺失或不可比证券进入未排名集合并保留原因，而不是从分母中静默消失。
6. 作为研究用户，我希望先保存完整批量结果，再对有限候选做深入研究；某个候选失败不能破坏全市场扫描结果。
7. 作为调用者，我希望大型结果只写入我显式指定的位置，运行中断后可以安全恢复，完成后任何改动都能被摘要校验发现。
8. 作为维护者，我希望开发 Ticket 不等待交易时段；只有最终冻结候选的盘中 live attestation 需要一次合格交易会话。

## v0.4.0 范围

### 综合市场五项正式能力

`market_overview_research@2.0` 保留 v0.3.0 已有十项市场能力，并将以下五项从 `unsupported` 变为具有正式 operation obligation 的能力：

| capability_id | tier | v0.4.0 最小语义 |
|---|---|---|
| `market_trading_session` | core | 交易日、Asia/Shanghai 当前阶段、适用交易所和阶段证据 |
| `major_broad_indices` | core | 固定四指数的同口径点位、涨跌、观测时间和来源谱系 |
| `whole_market_turnover` | core | SSE、SZSE、BSE A 股成交额分区及可比时才形成的总计 |
| `whole_market_margin` | standard | 适用交易所公开的融资与融券汇总分区、报告日期和发布时间 |
| `market_wide_intraday` | deep | 当前有效会话内，同一时点容差下的会话、指数、成交额和市场广度快照 |

`major_broad_indices@1.0` 的固定集合为：

- `SSE:000001` 上证综合指数；
- `SZSE:399001` 深证成份指数；
- `SZSE:399006` 创业板指数；
- `BSE:899050` 北证 50 成份指数。

该集合是 v0.4.0 的完整产品契约，不代表所有指数。它依据交易所公开定义固定：上交所的[上证系列指数简介](https://www.sse.com.cn/market/sseindex/overview/)、深交所对[深证成指 399001](https://www.szse.cn/disclosure/notice/general/t20150320_501397.html)和[创业板指 399006](https://www.szse.cn/disclosure/notice/general/t20100531_500454.html)的公告，以及北交所对[北证 50 899050](https://www.bse.cn/important_news/200013826.html)的通知。后续增删指数必须提升 capability 或 workflow 版本，不能在同版本静默变化。

全市场成交额只包含三交易所 A 股股票成交额。基金、ETF、债券、B 股、期权及单一指数成交额不进入该总计。各交易所的范围、单位、交易日或观测时间不能对齐时，只保留分区值并把汇总标为不可计算。

全市场两融保留各适用交易所的融资余额、融资买入额、融券余量或余额及其实际可得字段；不同交易所未证明同口径的字段不相加。某交易所依法或事实上不适用某字段时，必须有正式规则证据并记录 `not_applicable`，不能记录成成功空集。

`market_wide_intraday` 不是全证券逐笔流、五档盘口或分钟序列。它只组合交易会话、固定宽基指数、三交易所 A 股累计成交额和市场广度。当前会话不适用时，显式 deep 请求以 `skipped_research_dependency` 保留原因，其他市场研究仍可返回；不得伪造最近一次快照为当前盘中状态。活动会话的新鲜度和跨来源时差沿用现有盘中契约的 60 秒上限。

### 时点化全 A 股证券池

全 A 股定义为研究日期所对应完成交易日上，SSE、SZSE、BSE 正式证券清单中的人民币普通股票。证券池必须：

- 使用规范身份 `SSE:<code>`、`SZSE:<code>` 或 `BSE:<code>`；
- 从交易所或已经通过 operation-specific 资格的来源证明交易所、代码、名称、证券类别和生效时点；
- 保留上市、暂停上市、终止上市、停牌等可证明状态和生效区间，不从当前名单反推历史名单；以 `screen_date` 的三交易所正式 A 股清单建立 expected universe，能正向证明上市区间不覆盖 `screen_date` 的已观测记录以 `excluded_universe` 和原因保留审计但不进入排名分母；清单内证券的上市状态或生效区间尚未证明时不得静默删除，仍保留在 expected universe，并以 `listing_state_unproven` 或 `as_of_unproven` 进入 unranked；
- 不从代码前缀猜测交易所，不把新三板证券、基金、债券、B 股或指数混入 A 股分母；
- 分别报告三个交易所的 expected、resolved、acquired、ranked、unranked、failed 和 unsupported 数量；
- 只有三交易所身份分区都完整闭合，结果才可以称为“全 A 股”。SSE 与 SZSE 的并集不能代理全 A 股。

请求的 `as_of` 可以是交易日、周末或节假日。筛选 Module 使用不晚于 `as_of` 的最近一个三交易所共同完成交易日作为 `screen_date`；如果 `as_of` 是尚未结束的当前交易日，则使用前一个共同完成交易日。结果同时公开 `requested_as_of`、`information_cutoff` 和 `screen_date`，因此普通筛选不需要等待开盘。

`information_cutoff` 在历史 `as_of` 上是该日 Asia/Shanghai 23:59:59，在 `as_of` 等于当前本地日期时是实际 aware `research_now`；未来 `as_of` 失败关闭。价格和成交额锚定 `screen_date`，证券身份和财务输入必须证明不晚于 `information_cutoff` 已经生效或公开。后来取得的数据仍保留实际 `retrieved_at`，但不得把 cutoff 之后才公开的事实回填到历史排名。

### 能力驱动的来源资格

v0.4.0 不恢复“探测并处置固定 47 个端点”的版本目标。来源工作从本 Spec 的正式 capability 和固定筛选因子反推所需 operation：

1. 先枚举当前实现可复用的正式 operation；
2. 仅对尚无合格 owner 的具体能力登记候选 operation；
3. 优先检查交易所等第一方来源，再检查已有依赖中成熟、许可和运行边界可接受的来源；
4. 以 operation 为单位记录范围、字段、时点、单位、分页、空结果、失败、凭据、限流、依赖、许可、字段去向和适用用途；
5. 只有被固定计划实际调用的 operation 才进入 v0.4.0 正式分母。

发布证据继续区分执行事实与来源结果。正式来源结果保留 `complete`、`observed_empty`、`partial`、`credential_blocked` 和 `unavailable`；`attempted` 只从公共应用的实际执行状态派生，不被改写成来源成功状态。一个 release-critical capability 至少需要一个 owner 在冻结候选 live evidence 中产生 `complete`、语义有效的 `observed_empty`，或该 capability 明确允许的 `partial`；`credential_blocked` 和 `unavailable` 可以如实保留，但不能成为核心能力唯一的完成证据。

### 固定筛选计划

v0.4.0 只发布一个内置筛选计划：`fundamental_research_priority@1.0`。它只回答“哪些证券应优先进入下一轮基本面研究”，不回答“哪些证券值得买”。

#### 排名资格

证券必须同时满足以下条件才能排名：

- 在 `screen_date` 为可证明的正式 A 股上市证券；
- 至少有 20 个不晚于 `screen_date` 的完整成交日成交额；
- 可取得正数 `PE-TTM`、正数 `PB-MRQ`；
- 可取得归母净利润 TTM、当前 MRQ 归母权益和上年同期归母权益，且用于计算的平均归母权益为正数；
- 所有字段具有同一规范证券身份、明确单位、适用报告期、`available_at` 和来源谱系；
- 没有影响任一排名输入的未解决核心冲突。

expected universe 中不满足排名条件的证券仍保留在 universe 和 factor 分区中，以一个或多个稳定 reason code 进入 unranked。至少包括：`listing_state_unproven`、`insufficient_trading_sessions`、`non_positive_pe_ttm`、`non_positive_pb_mrq`、`missing_profit_ttm`、`missing_parent_equity`、`non_positive_average_parent_equity`、`missing_turnover`、`source_failed`、`scope_conflict` 和 `as_of_unproven`。不得补值、降低分母或按已有因子重新分配权重。

#### 因子与数学

四个因子都采用“越大，研究优先级越高”的方向：

| factor_id | 定义 | 权重 |
|---|---|---:|
| `earnings_yield_ttm` | `1 / PE-TTM` | 35% |
| `book_to_price_mrq` | `1 / PB-MRQ` | 25% |
| `return_on_equity_ttm` | `归母净利润 TTM / ((当前 MRQ 归母权益 + 上年同期归母权益) / 2)` | 25% |
| `median_turnover_amount_20_sessions` | 最近 20 个完整成交日成交额的中位数，单位 CNY | 15% |

每个因子在全体合格证券上独立计算升序 mid-rank percentile：并列值共享平均名次；`n > 1` 时为 `100 * average_zero_based_rank / (n - 1)`，`n = 1` 时固定为 `50`。最终分数为四个 percentile 与固定权重的 Decimal 加权和，使用 round-half-even 保留六位小数。禁止二进制浮点、NaN、Infinity、隐式 winsorization 和 Agent 重加权。

公开排序键固定为：

1. `research_priority_score` 降序；
2. `canonical_security_id` 升序。

同分证券必须公开 `score_tied: true` 和相同的分数名次；第二排序键只保证稳定输出与有界候选选择，不表示投资优劣。所有排名字段、因子值、单位、输入 observation 引用、计算公式版本和 unranked reasons 都进入结果包。

### 有界候选深研

`market_screen_research@1.0` 的 `completeness_mode` 固定为：

- `fast`：完成全市场证券池、因子和排名，不执行候选深研，`candidate_limit` 必须省略或为 `0`；
- `standard`：默认对前 5 个稳定排序候选执行 `single_security_research@1.0`，调用者可显式设置 `candidate_limit` 为 `1`–`20`。

候选深研使用相同的 `requested_as_of` 和 `information_cutoff`，行情价格仍锚定同一 `screen_date`，不得引入 cutoff 之后才公开的数据。每个候选是独立步骤：一个候选失败只降低该候选状态，不能删除或重写已经完成的 universe、factor、ranking 或其他候选结果。深研结果保存为结果包内独立、带摘要的 JSON 文件；统一结果只保留有界摘要和安全 artifact 引用，不复制全部候选结果。

### 公共请求与大型结果包

唯一外部 Interface 仍为：

```text
<python> <skill-root>/scripts/entrypoint.py run --request <research-task.json> [--output <file>]
```

`--output` 继续只保存与 stdout 完全相同的统一结果 JSON，语义不变。大型筛选结果由 workflow input 显式指定独立目录：

```json
{
  "schema_version": "1.0",
  "task_type": "research_workflow",
  "subjects": [],
  "as_of": "2026-08-21",
  "window": null,
  "parameters": {
    "workflow": {
      "id": "market_screen_research",
      "version": "1.0"
    },
    "inputs": {
      "screening_plan": {
        "id": "fundamental_research_priority",
        "version": "1.0"
      },
      "completeness_mode": "standard",
      "candidate_limit": 5,
      "result_artifact": {
        "path": "/absolute/caller-owned/a-share-screen-2026-08-21",
        "mode": "create"
      }
    }
  },
  "source_policy": {
    "allow_experimental": false,
    "allow_credentials": false,
    "allow_fallback": true
  }
}
```

`result_artifact.path` 必须是绝对路径。运行时在计划编译前解析并移除真实路径；公共结果、日志、诊断、夹具和候选深研文件不得复制该路径，只公开 `artifact_id`、schema、状态、文件计数、记录计数和摘要。缺少显式 artifact 配置的筛选请求失败关闭，因为全市场记录不能被压缩进当前有界统一结果。

`mode` 只接受：

- `create`：目标必须不存在；运行时以独占方式建立新 partial 目录；
- `resume`：目标必须是未 finalize 的同一请求 partial 目录，且请求摘要、producer 摘要、plan 摘要、operation manifest 摘要、artifact schema 和已有分区摘要全部一致。

请求语义摘要从移除整个 `result_artifact` 对象后的严格 ResearchTask 形成；目录路径和 `create`/`resume` 传输动作不改变研究语义，否则一次合法 resume 永远无法匹配初次 create。真实路径和 mode 只影响当次内存中的执行策略，不进入公共 receipt、checkpoint、manifest 或其他 artifact 文件。

结果包至少包含：

```text
checkpoint.json
partitions/universe/SSE/part-00000.jsonl
partitions/universe/SZSE/part-00000.jsonl
partitions/universe/BSE/part-00000.jsonl
partitions/factors/SSE/part-00000.jsonl
partitions/factors/SZSE/part-00000.jsonl
partitions/factors/BSE/part-00000.jsonl
partitions/ranking/SSE/part-00000.jsonl
partitions/ranking/SZSE/part-00000.jsonl
partitions/ranking/BSE/part-00000.jsonl
candidates/<safe-canonical-id>.json
manifest.json
```

上例中的 `part-00000` 表示按 canonical security 范围形成的稳定、有限 shard；实际文件数由 manifest 声明，不能依赖 provider 分页顺序。JSONL 使用 UTF-8、每行一个对象、键排序、禁止非有限数、Decimal 字符串和文件末尾换行。manifest 对每个文件记录相对路径、schema version、SHA-256、字节数和记录数，并记录请求语义摘要、producer 摘要、plan 摘要、operation manifest 摘要、三个交易所 coverage 计数及 artifact 状态。manifest 最后原子写入；只有 manifest 存在且全部摘要复验通过时才是 `finalized`。

运行时不得覆盖、追加或自动删除 finalized 结果包。这里的“写一次”表示工具协议拒绝改写，“可验篡改”表示任何后续文件变化会使 manifest 或公共 receipt 校验失败；它不声称依赖普通文件系统提供物理不可变性。

可恢复执行只重用已通过 checkpoint 和文件摘要复验的完整 shard，不重写完成 shard；未完成 shard 只保留在未提交的 working 状态，resume 从其明确 checkpoint 继续或重新形成该 shard，绝不能把它冒充完整记录。来源失败或正常中断保留 partial 包；显式 `resume` 才继续。若请求、代码、计划、正式 operation 集合或任何已有字节发生漂移，resume 失败关闭。工具不自动把历史 partial 包当作新请求输入。

## 深 Module 设计

### 外部 Interface

调用者只理解 ResearchTask、UnifiedResearchResult、显式结果包配置和失败模式。不存在来源专用公共命令、筛选专用第二 CLI、provider 端点 Interface 或第二研究结果模型。

### Market Foundation Module

该 Module 隐藏交易日历、会话分类、固定指数集合、交易所分区、口径对齐和盘中 fold。它通过内部 operation Adapter Seam 消费正式 owner：

```text
execute(OperationRequest, timeout) -> OperationOutcome
```

生产 Adapter 和确定性测试 Adapter 是该 Seam 的两个 Implementation。Interface 测试只断言 operation-owned outcome 和公共研究结果，不依赖 provider helper、URL 或 registry 布局。

### Universe and Batch Acquisition Module

该 Module 隐藏三交易所证券池归一化、分页、批量字段请求、共享限流、字段去向、as-of 裁决和失败分区。每个 operation 必须声明有限 page/request budget；运行时最多并行三个独立 provider group，同一 provider group 共享节流。存在合格批量 owner 时，不得为等价市场字段对每只证券重复执行无界单证券请求。

### Screening Module

该 Module 只消费规范化、时点合格的 factor records，执行固定计划的资格判断、percentile、Decimal 加权、排名和 unranked reasons。它没有网络、文件系统或 Agent 判断。因而同一输入字节和同一计划版本必须产生相同排名字节。

### Result Artifact Module

该 Module 隐藏安全路径解析、exclusive create、checkpoint、resume、canonical JSONL、摘要和 finalize。它对上只暴露小型内部 Interface：写入已完成分区、写入候选结果、记录 partial 状态和 finalize receipt。生产文件系统 Adapter 与确定性测试 Adapter 使用同一契约；不得把文件 helper 提升为公共 Interface。

### Candidate Research Module

该 Module 只选择固定排序后的前 N 个 canonical IDs，并复用现有 `single_security_research@1.0` Interface。它不复制单标的来源逻辑，不形成第二套估值、材料或市场方案。

这些 Module 形成四个主要变化 Seam：外部来源、文件系统、固定筛选计划和候选 workflow。新增 Module 必须隐藏实质复杂度；只转发参数、复制 schema 或包装一个函数的浅层 Implementation 不进入正式架构。

## 运行状态与失败传播

- 有效 JSON 研究结果继续使用退出码 0，包括 `supported`、`limited`、`blocked` 和具有 partial artifact 的结果。
- 请求 schema、artifact 路径、resume 摘要、I/O 或内部协议失败使用非零退出码；stdout 不输出半个 JSON。
- 一个交易所 universe 不完整时，结果不得称为全 A 股；已有分区和 unranked/failed 记录仍保留。
- 一个 factor owner 失败只使依赖它的证券或因子不可排名，不删除其他有效证券记录。
- 一个候选深研失败只降低该候选，不改变全市场 score 或排名。
- 全市场聚合口径不兼容时保留分区 observation，汇总 calculation 不生成。
- `observed_empty` 只表示完整查询证明零条；分页不完整、权限阻断和来源异常分别保留 `partial`、`credential_blocked` 或 `unavailable`。
- provider raw payload、请求头、凭据、服务器信息、本地绝对路径和未脱敏异常不进入公共结果或 artifact。

## 非协商不变量

1. 唯一公共命令和唯一 UnifiedResearchResult 保持不变。
2. `schema_version: "1.0"` 不接受同版本旧形状或未知字段；workflow 版本按 ID 精确验证。
3. `market_overview_research@2.0` 的五项新增能力具有正式 owner，不再以 `unsupported`、单证券、ETF、单一指数或板块 proxy 交付。
4. 全 A 股结论必须包含 SSE、SZSE 和 BSE 三分区；BSE 缺失时失败关闭该结论。
5. 筛选使用的价格、成交额和交易日事实锚定且不晚于 `screen_date`；证券身份和财务事实必须不晚于 `information_cutoff` 已经生效或公开；任何事实都不得晚于 `information_cutoff`，不产生前视偏差。
6. 因子、权重、缺失规则、percentile 和排序键只在版本化计划中定义一次。
7. 缺失因子不补值、不重加权；未排名证券保留身份和原因。
8. 排名和候选选择是确定性的；Agent 不参与分数计算或权重决定。
9. 结果包必须显式创建、可恢复、写一次、可验篡改；finalized 包不被工具修改或删除。
10. operation ownership、字段去向、七态 runtime coverage 和 release source-result 状态保持各自唯一真相。
11. 开发和确定性验收不依赖 live provider；最终 live attestation 只对冻结 clean candidate 执行。
12. 适当性、投资动作、仓位、杠杆、五档盘口和逐笔成交不进入本版本。
