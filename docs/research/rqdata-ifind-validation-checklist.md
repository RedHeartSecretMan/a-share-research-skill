# RQData 与 iFinD：许可询问和登录态验证清单

状态：等待项目所有者向供应商确认并自行取得试用或正式账号。本文不构成法律意见，也不表示任何提供方已经准入。

依据：[Adapter 准入矩阵](adapter-qualification-matrix.md)

## 目标

按“单个 Adapter 操作”验证 RQData HTTP 和 iFinD HTTP 是否能支撑 SSE、SZSE 当前估值证据链，并确认本项目所需的数据使用权。第一顺位验证 RQData，只有它被阻断或需要独立交叉核验时再进入 iFinD。

验证期间不得实现生产 Adapter，不得向仓库提交真实授权响应、原始数据缓存或供应商材料。HTTP 200 不是通过条件。

## 项目使用场景说明

向供应商说明以下真实使用方式，不要只询问“API 能不能用”：

- 项目是 Apache-2.0 开源、平台中立的 AI Agent Skill。
- 用户在自己的机器上配置自己的数据账号；项目不共享、代理或转售账号。
- 开源代码可能自动调用正式 HTTP API，取得单标的、低频、日终研究所需的最小数据。
- CLI 会对价格、股本和公开财务值做口径校验，并派生总市值、PE TTM 和 PB MRQ。
- 输出包含支持结论所需的少量原始规范化值、来源标识、日期、单位、口径和限制，不输出或镜像供应商全量数据库。
- 开发需要合成夹具；只有供应商明确允许时，才会保存或公开最小脱敏真实响应片段。
- 项目本身可以被个人或机构用于非商业或商业研究环境，因此不能默认依赖“仅个人非商业”许可。

## 共同许可问题

要求供应商逐项书面回答，并指出适用合同条款：

1. 是否允许用户通过项目发布的开源 Adapter 自动调用其本人已授权的正式 API？
2. 是否允许在用户本机短期缓存单标的、低频响应？允许的期限和删除要求是什么？
3. 是否允许输出少量原始规范化事实及来源标识，用于支撑派生估值结果？
4. 是否允许输出由这些事实计算出的总市值、PE TTM 和 PB MRQ？
5. 是否允许公开不含凭据和真实数据的 Adapter 源代码、字段映射、错误映射及合成测试夹具？
6. 是否允许保存不含证券真实值的 schema 摘要、字段名、类型、错误码和限流诊断？
7. 若允许最小真实夹具，允许的字段、脱敏方式、保存期限和公开范围是什么？
8. 个人研究、企业内部研究、面向客户的研究输出和商业软件集成分别需要什么产品与许可？
9. 哪些行为被视为数据再分发、衍生作品、第三方系统接入或变相数据服务？
10. 若合同与公开网站协议不同，以哪一份文件为准，是否可以取得可归档的书面确认？

任一关键使用方式没有明确授权时，对应操作保持 `当前 NO-GO`。

## RQData 询问模板

主题：确认 RQData HTTP API 在开源本地研究 Skill 中的接口权限与数据使用范围

```text
您好：

我们正在开发一个 Apache-2.0 开源、在用户本机运行的 A 股研究 Skill。用户使用自己的 RQData 账号，通过官方 HTTP API 低频获取单标的日终行情、停牌状态、有效总股本和 Point-in-Time 财务数据；本项目计算总市值、PE TTM、PB MRQ，并输出少量支撑数值、来源与日期，不镜像或转售数据库。

烦请确认：

1. 哪种试用或正式产品覆盖 all_instruments、交易日历、不复权 get_price、is_suspended、get_shares、公司行动、get_pit_financials_ex、net_profit_parent_company 和 equity_parent_company？
2. 上述 Python 方法到 HTTP method 的正式映射、字段字典、单位、版本和错误契约在哪里？
3. SSE、SZSE 与 BSE 分别支持哪些代码、交易日历、行情、股本和 PIT 财务操作？
4. 无权限、超配额、过期 token、错误字段、未知证券、无数据、部分响应和数据未就绪分别如何返回？
5. 正式产品的模块、历史范围、QPS、并发、日配额、数据保留、SLA 和价格如何确定？
6. 请按所附“共同许可问题”确认自动调用、本地缓存、少量事实与派生指标输出、开源 Adapter、合成夹具、最小真实夹具及商业下游的许可边界。
```

## 登录态验证前置条件

只有同时满足以下条件才开始一次性原型：

- 项目所有者已自行注册或购买适用账号，并接受供应商条款。
- 供应商已经明确试用/正式模块包含待验证操作。
- 项目所有者在本机秘密存储或进程环境中配置凭据；凭据不会发到聊天、Issue、命令行参数或仓库文件。
- 已明确验证期间允许保留哪些响应；未明确时只记录字段名、类型、状态、错误码和布尔通过结果。
- 原型目录被明确视为可删除的临时工作区，不属于安装 Skill 或生产代码。

## 一次性原型顺序

### 1. 认证与最小读取

- 验证认证成功、过期和无权限三种路径。
- 记录 HTTP 状态、供应商错误码、content type、schema 摘要和重试提示。
- 不记录认证请求正文、token、用户名、手机号、机器码或完整响应头。

### 2. 身份与市场

- SSE 主板、SSE 科创板、SZSE 主板、SZSE 创业板各一只。
- BSE 一只当前 `920` 代码证券；不支持时明确记录。
- 非法代码、退市代码和错误交易所各一例，必须 fail closed。

### 3. 交易日、价格与状态

- 正常交易日、全天停牌、除权日、周末/休市日和未来日期。
- 验证价格明确为不复权，并禁止用前值填充冒充当日成交。
- 验证最近完成交易日与交易状态能由独立字段确认。

### 4. 有效总股本

- 回购注销、增发、送转、限售变化和同日多事件各一例。
- 验证单位、精度、生效日、普通股类别和多市场发行主体行为。
- 对照法定公告，不用供应商派生市值反推股本。

### 5. PIT 财务与版本

- 首次披露、同日更正、跨日更正、调整前/后、缺失上年同期各一例。
- 取得上一完整年度、本年最新累计期、上年同期累计期三段归母净利润原值。
- 取得最近公开报告的归属于母公司股东权益。
- 按本项目公式重建 TTM，供应商 TTM 只用于交叉核验。

### 6. 失败与漂移

- 超配额、限流、错误方法、错误字段、未知证券、无数据、部分数据、数据未就绪、4xx、5xx 和列漂移。
- 每种失败必须能归一化为明确原因，不能返回 HTTP 200 后静默形成空证据。

## 原型留存物

默认只允许提交以下脱敏材料：

- 验证日期、提供方、产品模块和 API 文档版本；
- 操作名、请求参数名称，不含凭据和真实账号标识；
- HTTP 状态、供应商错误码、字段名、数据类型和 schema 摘要；
- 合成后的最小成功/失败夹具；
- 每个准入条件的通过、阻断或未验证结论；
- 供应商书面答复的内部引用位置，不公开合同或受限文本。

除非供应商明确书面允许，不提交真实价格、股本、财务数值、完整响应、PDF、截图、合同、token 或账号资料。

## 通过门槛

一个 Adapter 操作只有同时满足以下条件才能进入生产规格：

1. 正式 HTTP 契约覆盖字段、单位、时间、版本、错误和限流。
2. Python 3.12 标准库可跨 Windows、macOS、Linux 调用。
3. 正常、边界和失败样本均 fail closed。
4. 研究时点、未复权、停牌、股本生效和 PIT 语义已经验证。
5. 项目所需的自动访问、最小事实输出、派生估值、开源 Adapter 和测试策略已经得到适用书面许可。

只要其中一项不满足，该操作继续保持候选、个人可选、未验证或 NO-GO，不因同一品牌的其他操作通过而自动准入。
