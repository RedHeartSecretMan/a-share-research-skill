## 当前闭包

v0.3.0 的正式来源操作分母由版本化公共计划中的 `operation_obligations[].producer_operation_id` 唯一确定。最终矩阵包含 44 个不重复操作，并闭合以下三项门禁：

- 正式操作处置：44/44；
- 默认安装加载：44/44；
- active-request 字段去向：740/740。

最终证据绑定运行时候选 `7acb445cdccb9f8311d0a1d094f195eb0d7229e2`，验证时点为 `2026-08-18T11:24:17+08:00`。27/27 个发布请求画像形成有效公共计划，44/44 个正式来源操作均至少出现一次真实 `succeeded` 或 `failed` 执行状态。

“已尝试”只说明公共应用实际到达来源操作。它不表示来源返回了可用数据，也不表示来源整体通过生产准入。最终 44 个来源结果中仍保留 `complete`、`observed_empty`、`partial`、`credential_blocked` 和 `unavailable`。

## 三份版本化证据

- [`v0.3.0-operation-qualification.json`](v0.3.0-operation-qualification.json) 是逐操作审阅的资格清单。每项绑定实际 owner contract、离线测试、时点、单位、失败、空集、凭据和限流语义。
- [`v0.3.0-release-probe-evidence.json`](v0.3.0-release-probe-evidence.json) 是维护者通过复制安装后的公共 `run --request` 入口形成的最终脱敏证据。它保留候选 SHA、带时区验证时点、请求画像、计划快照、安装加载和逐操作尝试状态，不保存凭据、完整供应商载荷或服务器诊断。
- [`v0.3.0-operation-release-matrix.json`](v0.3.0-operation-release-matrix.json) 完全由前两份证据通过 typed builder 派生。测试按字节检查它是否陈旧；不得手工修改操作 ID、字段或汇总比率。

同一正式操作可以出现在多个任务、工作流步骤或估值比较成员中。矩阵将这些位置保留为 applications，但不会重复扩大 44 操作分母。每个 application 保留自己的 task-local `field_dispositions`，避免把不同任务中的合法字段去向压成虚假的全局契约。

## 解释边界

- `integrated` 表示对应领域 Ticket 已通过确定性 owner contract 和复制安装公共 E2E 闭合；它不把 ResearchTask 中的 `experimental`、`allow_experimental`、coverage 或 evidence-adoption 语义改写为来源已获生产认证。
- `attempted: true` 只能由公开 application 的 `execution_state` 为 `succeeded` 或 `failed` 推导；`not_requested`、`skipped_policy` 和 `skipped_research_dependency` 都不计。
- `source_result` 单独表达来源结果。`unavailable` 是实际失败，不是未尝试；`observed_empty` 必须有完整空集证明，不能由空响应或来源错误推断。
- 单次来源成功只证明该次请求取得了观测，不证明未来可用性、许可、独立交叉资格或生产准入。

## 复验当前矩阵

从仓库根目录运行：

```text
<python> tests/generate_core_operation_release_matrix.py --check
```

成功时返回 `schema_version: "1.0"`、`status: "current"`、`operation_count: 44` 和当前矩阵 SHA-256。该命令不访问外部来源。

只有在资格清单或最终联网证据经过独立审计并有意更新后，才允许重写矩阵：

```text
<python> tests/generate_core_operation_release_matrix.py --write
<python> tests/generate_core_operation_release_matrix.py --check
```

## 为后续版本重新采集证据

下一版本需要重新联网验证时，先冻结一个干净候选提交，再为每次尝试使用独立且尚不存在的输出路径：

```text
<python> tests/release_probe_core_operations.py \
  --confirm-live \
  --verified-at <ISO-8601-with-timezone> \
  --as-of <YYYY-MM-DD> \
  --replay-date <completed-YYYY-MM-DD> \
  --attempt-output /private/tmp/release-probe-<candidate>-<attempt-id>.json \
  --failure-output /private/tmp/release-probe-failure-<attempt-id>.json \
  --output docs/research/<version>-release-probe-evidence.json
```

后续尝试为每个已验证的 prior artifact 增加一个 `--attempt-input <path>`。每个输入必须绑定同一候选、通过 digest/shape/profile/load/sample 闭包、具有带时区验证时点，并在最终组装时仍满足 7×24 小时新鲜度。最终 evidence 只在同候选 union 精确闭合全部正式操作后生成；未闭合的 partial attempt 保留在独立临时路径，不得冒充 final artifact。

复制安装与来源子进程只继承经过 URL 结构验证的 HTTP(S) 路由变量和有界 `NO_PROXY`；凭据、header、token、用户配置、完整载荷和供应商 stderr 不进入证据。失败输出只含固定脱敏诊断。
