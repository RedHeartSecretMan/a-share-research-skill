# Fixed Index Observations Module

This internal Market Foundation Module implements `execute(FixedIndexOperationRequest, timeout_seconds) -> OperationOutcome` for exactly `SSE:000001`, `SZSE:399001`, `SZSE:399006`, `BSE:899050`, in that order. It adds no public command, ResearchTask field, arbitrary index list or workflow cutover. `build_default_fixed_index_adapter` composes the production source owner and the existing #117 session owner without making a source call during construction.

## Ownership and internal use

The trusted internal composition supplies the #117 Adapter and request. Session create/restore, calendar authority and the original C digest stay with #117; persisted commitment and binding validation stay with #108. Arbitrary caller-provided context or outcome mappings cannot replace that invocation. Historical C remains usable even when its present-day session descriptor is unproved.

The existing fixed plan resolves `current_session` or `completed_session` before execution. Current use requires current authority and the applicable session date; restoration cannot silently change it into completed use. Completed `frozen_context` uses original C.screen_date. Completed `latest_index_session` uses #117's latest regular-auction session for a current-date request; historical requests retain C.screen_date. Purpose and completed basis are included in internal observation identity and payload.

When the latest regular auction has ended but scheduled full-day completion has not, a current source reports `completed_session_reported_value` against the regular-auction target. Its own quote/update clock must be on that date, at or after the exchange's proved auction end. It is not labelled final close, last trade or first publication. Restored contexts use the corresponding historical day and preserve the original purpose and target. The Module does not derive weekdays, phases or completed dates itself.

## Reviewed source bindings

Production acquisition consumes #121 K/L source evidence and M's available usage conditions. Each index has one selected direct request, no retry, redirect, alternate provider or alias. Calls are sequential; the operation deadline includes the session owner, each index request is capped at 20 seconds, and the operation timeout is finite and at most 120 seconds. Default wire reads stop at 256 KiB plus one overflow byte. The session owner retains its separate six-document budget. The existing HTTP invocation bridge owns leaf counting and cancellation when the caller runs the operation in a provider execution. Deadline checks reject late results; this Module does not independently certify worker quiescence. History windows are bounded source windows, not a claim of unlimited historical coverage or pagination completeness; a missing target or baseline fails explicitly.

## Values, projection and failure

Reported finite Decimal strings, raw source fields, native clock tokens and baseline provenance are preserved. BSE percentage scaling is exact. SSE daily change and percentage are explicitly derived, with formula, decimal precision and input lineage. Exact synthetic arithmetic uses an independent Decimal context. Reported arithmetic uses joint feasibility within one source display quantum (SSE/BSE 0.01; SZSE reported resolution capped at 0.01). This bounded consistency policy accommodates documented display precision without guessing hidden tie rounding or rewriting reported values; it does not permit arbitrary error.

Positive index points and baseline, units, semantics, chronology and provenance are required. Missing, duplicate, unexpected, stale, conflicting, impossible or oversized rows produce constant bounded errors; independent valid indices survive. No rows means failed, never observed_empty. One-pass input snapshots, recursive immutable storage and fresh detached plain JSON are owned by #116. Payloads reference the #117 operation and C digest without nesting sibling-owned proof. Copied-installed loading and public-result references pass through the same operation Interface.
