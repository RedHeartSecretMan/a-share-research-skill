# 分时复盘情景预测边界案例

本案例只说明安装后 Skill 的 Agent 路由与回答结构，不保存来源响应，也不把预测加入 `intraday_replay` 的确定性 JSON。`intraday_replay` 仍只返回来源事实、覆盖裁决和计算；历史查询或分时复盘请求只有在用户明确要求未来判断时才进入本案例。这是一条显式请求边界。

## 请求触发与证据门槛

普通身份查询、收盘查询、走势研究或 `intraday_replay` 历史复盘不附加预测。明确提出“预测下一交易日和未来 5 个交易日”后，先取得同一规范证券和复盘日的确定性结果，再核验：

- 规范证券身份；
- 非 `blocked` 且有可用收盘价或收盘阶段的复盘；
- 截至复盘日的 20 个完整日线交易日；
- 证券、日期、未复权价格口径与收盘价一致；
- 没有未解决的核心来源冲突。

## 五类路径

| 路径 | 结果边界 | 回答要求 |
| --- | --- | --- |
| 正常预测 | `supported` | 两个固定周期各给一个主情景和上下行替代情景，并保留全部证据字段。 |
| 证据不足拒绝 | `blocked` | coverage 不可判定、缺少收盘、整个上午或下午缺失、日线不完整或确认全天停牌时拒绝，并列出需要补齐的证据。 |
| 部分证据 | `limited` | 收盘可用且缺口有界时最多形成受限预测；逐项列出缺口和受影响的判断。 |
| 可选上下文缺失 | 不自动阻断 | 缺少公告、新闻、资金流、资本事件、估值、行业或大盘材料时，披露上下文缺口，只把结论限制在价格行为，不虚构原因或主力意图。 |
| 禁止投资行动 | 始终拒绝该部分 | 不输出评级、目标价、买入/卖出/持有、仓位、止损、执行、提醒、订单或自动交易。 |

## 回答模板

先分层展示事实（正式 observations/claims）、可复算的 `calculations`、复盘分析和预测。预测只在明确请求且满足证据门槛后出现；没有真实可复算输入和样本外验证的模型，不写精确概率或伪统计置信度。

### 周期：下一个交易日

- 主情景：从延续、震荡、反转中选择一个；说明证据基础、支持与反向证据、假设、可观察触发、失效条件和不确定性。
- 上行替代情景：同样列出证据基础、反向证据、假设、触发、失效和不确定性。
- 下行替代情景：同样列出证据基础、反向证据、假设、触发、失效和不确定性。

### 周期：未来 5 个交易日

独立重复上述三情景结构；不能用一个周期的主情景代替另一个周期，也不能把任一情景写成确定结果。

本案例中的 `supported` 只表示回答结构满足证据门槛，不表示来源真实资格或未来结果已被证明；`limited` / `blocked` 必须原样披露，最终投资决定留给研究者。
